# NeuralAutoTune

Real-time neural pitch correction for the STM32N6570-DK, written as a
middleware for μT-Kernel 3.0.

Sher Amir Singh Dullat, TRON Programming Contest 2026 (TRON × AI)

You sing into the board's microphone and hear yourself in the headphones,
moved onto the nearest note of the selected key, about 9 ms later. Two neural
networks run on the STM32N6's Neural-ART NPU:

- a pitch tracker (based on SwiftF0), every 10 ms
- the RSN (residual synthesis network), every 5 ms. It regenerates the LPC
  excitation of the voice at the corrected pitch. The LPC envelope is left
  alone, so the formants, and with them the character of the voice, stay
  the singer's.

The signal processing, the networks and the scheduling are packaged as the
`natune` middleware. An application calls `natune_init()` and
`natune_start()`, then sets the key or mode when it wants to. The API is
described in [AppliNonSecure/natune/README.md](AppliNonSecure/natune/README.md).

## How it runs on μT-Kernel

```
mic -> MDF -> DMA irq --flag--> audio task (1 ms blocks)
                                  analysis, target pitch, RSN input
                                      |
                                      v  flag
            NPU irq --flag--> npu task: runs the RSN and the pitch
                              tracker, synthesizes each 5 ms hop
                                      |
headphones <- codec <- SAI <- DMA <-- audio task

USART irq -> ctrl task (serial commands, status)
usermain  -> app task (button and LEDs)
```

All interrupts are registered with `tk_def_int`. The audio and ctrl tasks
share the DSP state under a mutex with priority inheritance, and a 1 ms
cyclic handler drives the STM32 HAL tick.

## Results

Measured on the board; more detail in [docs/MEASUREMENTS.md](docs/MEASUREMENTS.md).

| | |
|---|---|
| RSN self-test on the NPU | passes (max 3 LSB off the host reference) |
| RSN inference | 2.9 ms |
| synthesis hops | 200 per second, none late |
| latency, mic to speaker (digital) | 8.85 ms |
| vowel sung 45 cents flat | 0.5 to 1.4 cents after correction |
| real singing (VocalSet clip) | 36 cents off the scale before, 2.2 after (median) |
| 30-minute stress test | no missed blocks out of about 1.8 million |
| worst 1 ms audio pass | 614 to 691 µs |
| kernel footprint | 12.6 KB code, 37 KB RAM |

These match the earlier bare-metal version of the same firmware.

## Building and running

You need the board in development boot mode (BOOT1 switch at 1-3) and
STM32CubeIDE 2.1.

1. File > Import > General > Existing Projects into Workspace. Select this
   folder, tick "Search for nested projects" and import all three projects
   (`RSN`, `RSN_FSBL`, `RSN_AppliNonSecure`). Leave "Copy projects into
   workspace" unticked; the projects use files from the folders around them.
2. Project > Build All.
3. Run > Debug Configurations > STM32 C/C++ Application > `RSN_FSBL`, then
   Debug. This loads the application, the RSN weights
   (`tools/board/blobs/rsn_weights.elf`) and the FSBL into RAM and stops in
   the FSBL's `main`. Press Resume.

The console is the ST-LINK virtual COM port at 2,000,000 baud.

Without the IDE (Python 3 with pyserial, numpy and scipy):

```
tools/board/board.sh run 20
```

This builds both images with make, loads them and the weights, starts the
board and shows 20 seconds of console output. To build only:
`cd AppliNonSecure && make`.

Plug headphones into the 3.5 mm jack and sing. USER1 changes the key (short
press) or turns correction off and on (long press). LD1 is on while
correcting, LD2 flashes on clipping. [tools/board/README.md](tools/board/README.md)
covers the serial commands and the test scripts.

## Layout

```
AppliNonSecure/     application image
  natune/           the middleware
  app/              sample application (usermain, button, LEDs)
  mtk3_bsp2/        μT-Kernel 3.0 and BSP2
  Core/             board bring-up generated by STM32CubeMX
  X-CUBE-AI/        network code generated by ST Edge AI
  Middlewares/      ST Neural-ART runtime
FSBL/               secure boot stage: clocks, firewalls, NPU power
Drivers/            STM32N6 HAL, CMSIS
tools/board/        build/load script, test bench, soak test
tools/rsn_v3/       RSN training
tools/swiftf0/      pitch tracker training
deploy/             the trained RSN
docs/               measurements, porting notes, licenses, Japanese summary
```
