# NeuralAutoTune(日本語概要)

STM32N6570-DK 上で動くリアルタイムのニューラル音程補正を、μT-Kernel 3.0 の
ミドルウェアとして実装しました。

作者:Sher Amir Singh Dullat(TRON プログラミングコンテスト 2026、テーマ「TRON × AI」)

## 概要

ボードのマイクに向かって歌うと、選んだキーの最も近い音に補正された自分の声が、
約 9 ms 後にヘッドホンから聞こえます。STM32N6 の NPU(Neural-ART)で
二つのニューラルネットワークを動かしています。

- ピッチ推定(SwiftF0 を元にしたもの):10 ms ごと
- RSN(残差合成ネットワーク):5 ms ごと。声の LPC 残差を補正後の音高で作り直します。
  LPC の包絡はそのまま使うので、声の特徴は歌い手のまま残ります。

信号処理、ネットワーク、スケジューリングを `natune` ミドルウェアにまとめました。
アプリケーションは `natune_init()` と `natune_start()` を呼び、必要に応じて
キーやモードを設定するだけです。

## μT-Kernel の使い方

- npu タスク(優先度 2):NPU を動かし、5 ms ごとに音声を合成
- audio タスク(優先度 3):1 ms ごとの音声処理。DMA 割込みからイベントフラグで起床
- ctrl タスク(優先度 12):シリアルコマンドと状態表示
- アプリタスク(usermain):ボタンと LED
- 割込みはすべて `tk_def_int` で登録
- audio と ctrl の間は優先度継承ミューテックスで排他
- 1 ms の周期ハンドラで STM32 HAL のティックを駆動

## 測定結果

- RSN の自己診断(NPU とホストの比較):合格
- RSN 推論時間:2.9 ms
- 合成:毎秒 200 回、締め切り超過なし
- マイクからスピーカーまでの遅延(デジタル部分):8.85 ms
- 45 セント低い母音:補正後 0.5〜1.4 セント
- 実際の歌声(VocalSet):36 セント → 2.2 セント(中央値)
- 30 分の連続試験:約 180 万ブロック中、取りこぼしなし
- カーネルの使用量:コード 12.6 KB、RAM 37 KB

以前のベアメタル版と同じ性能です。

## 移植で見つけた問題

1. BSP2 v1.00.04 の armv8m 用 `interrupt.c` に誤記(`sN_INTVEC`)があり、
   `tk_def_int` が使えませんでした。`N_INTVEC` に修正しました。
2. D キャッシュが有効だと、カーネルが RAM に置いたベクタテーブルへの書き込みが
   キャッシュに残り、最初の割込みで古いベクタを読んで停止しました。MPU で
   ベクタテーブルの領域をキャッシュ対象外にして解決しました(カーネルは無変更)。

詳しくは `PORTING.md` を参照してください。
